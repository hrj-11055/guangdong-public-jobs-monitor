# 数据结构

## 招考机会

一行代表一个招聘项目；需要做精确人岗匹配时，一行改为一个岗位。核心字段：

| 字段 | 规则 |
|---|---|
| 记录ID | 稳定唯一值，不随标题小修而改变 |
| 招聘性质 | 公务员/选调生/参公/事业编/编外/国企/待核实 |
| 地区、区县 | 广东省、广州市及 11 区 |
| 招聘单位、主管部门 | 使用公告原文名称 |
| 公告标题、公告阶段 | 首发/补充更正/报名/准考证/笔试/资格复审/面试/体检考察/公示/取消暂停 |
| 公告日期 | 真实日期值 |
| 报名开始、报名截止 | 真实日期时间；未知留空 |
| 招聘人数 | 数值；职位表未核验时留空 |
| 对象、年龄、学历、学位、专业 | 原文摘要，不做宽松解释 |
| 户籍、政治面貌、经历、资格证 | 无要求写“未见要求”，不是“无” |
| 考试科目、官方大纲 | 标记原文和附件 URL |
| 材料要求 | 正文摘要，详细拆到材料清单 |
| 报名入口、公告原文、附件 | 使用完整 URL |
| 核验状态 | 已核验/待复核/有更正/已失效 |
| 最近核验 | 北京时间 |
| 备注 | 冲突、风险、待办 |

## 关键时间点

一行代表一个动作，字段包括记录ID、事项、开始时间、截止时间、是否必须、完成状态、提醒时间、官方依据和备注。不要把考试预计时间当作报名截止时间。

## 信息源地图

与 `official-sources.json` 保持一致。字段包括来源ID、权威等级、来源名称、地区、类别、URL、官方性、来源角色、频率、是否启用、最近核验、抓取限制和备注。

## 材料清单

一行代表一类材料。使用 `通用/公务员/事业编/教师/医疗/特定岗位` 标签。`是否具备` 和 `有效期` 由候选人在私有副本中填写。

## 个人条件

只在私有副本填写。建议字段：出生日期、应届身份、最高学历学位、毕业日期、学校、专业名称与代码、户籍、政治面貌、基层经历、工作经历、服务基层项目、退役身份、资格证、可接受地区和岗位类别。

## 监控脚本输出

`data/notices.csv` 记录网页发现层，不等于已经完成附件核验的最终招考台账。字段包括：

- notice_id, source_id, source_name;
- authority_level, region, source_category;
- title, url, published_date;
- inferred_job_type, inferred_stage;
- first_seen, last_seen, current_run_new;
- verification_status.

`data/source_health.csv` 记录每个源的运行状态、HTTP 状态、耗时、候选链接数和错误。
